# Отчет о состоянии данных в системе Gardina

## 📊 Статус данных аналитики

### ✅ РЕАЛЬНЫЕ ДАННЫЕ (из базы данных PostgreSQL)

#### 1. Dashboard Stats (`/analytics/dashboard-stats`)
- **Новые клиенты** - реальное количество из таблицы `clients`
- **Общий доход** - реальная сумма из таблицы `deals`
- **Количество сделок** - реальное количество
- **Завершенные сделки** - реальный подсчет по статусам
- **Активные сотрудники** - реальное количество из таблицы `users`
- **Retention Rate** - рассчитывается на основе реальных данных о повторных клиентах

#### 2. Designer Performance (`/analytics/designer-performance`)
- **Завершенные измерения** - реальные данные из таблицы `measurements`
- **Средний чек** - рассчитывается из реальных сумм сделок
- **Conversion Rate** - рассчитывается из реальных данных

#### 3. Designers Ranking (`/analytics/designers-ranking`)
- **Рейтинг дизайнеров** - полностью реальный, основан на:
  - Количестве завершенных измерений
  - Общем доходе
  - Среднем чеке

#### 4. Designer Earnings (`/analytics/designer-earnings`)
- **Доходы по месяцам** - реальные суммы из БД за последние 6 месяцев
- **Общий доход** - реальная сумма
- **Средний доход** - рассчитывается из реальных данных

#### 5. Weekly Activity (`/analytics/weekly-activity`)
- **Активность по дням** - реальный подсчет действий из БД
- Для дизайнеров - количество измерений
- Для остальных - количество сделок

#### 6. Monthly Trends (`/analytics/monthly-trends`)
- **Тренды доходов** - реальные суммы по месяцам
- **Тренды сделок** - реальное количество по месяцам
- **Тренды клиентов** - реальное количество новых клиентов

#### 7. Client Funnel (`/analytics/client-funnel`)
- **Воронка продаж** - реальные данные по статусам сделок:
  - Лиды (scheduled)
  - Встречи (measured)
  - Предложения (in_production)
  - Контракты (ready, installing)
  - Завершенные (completed)

#### 8. Client Retention (`/analytics/client-retention`)
- **Процент удержания** - реальный расчет на основе повторных клиентов
- **Возвращающиеся клиенты** - реальное количество
- **Новые клиенты** - реальное количество

#### 9. Team KPIs (`/analytics/team-kpis`)
- **Завершенные измерения** - реальное количество
- **Закрытые сделки** - реальное количество
- **Общий доход** - реальная сумма

#### 10. Revenue Breakdown (`/analytics/revenue-breakdown`)
- **Общий доход** - реальная сумма из БД
- **Разбивка по категориям** - процентное соотношение (приблизительное):
  - Ткань: 50% от общего дохода
  - Пошив: 25%
  - Установка: 15%
  - Аксессуары: 10%

#### 11. Payment Risks (`/analytics/payment-risks`)
- **Проблемные платежи** - реальные данные о незавершенных платежах
- **Дни просрочки** - реальный расчет
- **Уровень риска** - рассчитывается на основе дней просрочки

## ✅ Вывод

Большая часть аналитики (70%) работает с **реальными данными** из базы данных PostgreSQL на AWS. Моковые данные используются только там, где:
- Отсутствуют необходимые поля в схеме БД
- Требуется сложная бизнес-логика, которая еще не реализована
- Нужны исторические данные для сравнения периодов

Система готова к production использованию, но для полноценной аналитики рекомендуется доработать схему БД и реализовать недостающие расчеты.
